# editor/ (Kerf Editor)
TypeScript PWA for Chrome/Edge desktop. paper.js for geometry, opentype.js for text. Internal units mm; Design/Bed/Screen/Camera spaces per brief section 5; Bed→Screen conversion lives in ONE function. Edits change object matrices, never source geometry. Export DXF/SVG must work standalone. Does not talk to hardware directly (no Web Serial).

## Commands (run from `editor/`)
- `npm install`, `npm run dev` (Vite dev server), `npm run build` (typecheck + bundle), `npm test` (vitest), `npm run typecheck`.
- Machine profiles are imported from `../shared/machine-profiles` at build time (`src/machine.ts`).
- `src/coords.ts` holds Bed<->Screen conversion; do not convert elsewhere. `public/sw.js` is the offline app-shell cache (it caches the Editor at `/editor/`, never the website as the Editor).

## Modules
- `geometry.ts` (segments/matrices/shapes), `select.ts` (box select), `tabs.ts` (tabs/bridges: stored on `DocObject.tabs` as fractions along the closed Cut outline plus a width in mm; `splitByTabs` turns them into the open pieces the laser cuts, applied in DXF/SVG export and, later, G-code), `repair.ts` (join loose segments into paths with a bucketed tolerance match, close, explode, and node move/insert/delete; DXF import auto-joins per layer), `fillet.ts` (also `roundedRectangle`; corner radius/chamfer of straight-line corners as true arcs; clamps to half of each edge), `icons.ts` (tool icon set + sprite), `arrays.ts` (linear repeat, circular array, mirror), `testgrid.ts` (material test grid and kerf coupon generators; cells record per-shape power/speed in `DocObject.settings`), `boxnet.ts` (Tools > Box net: flat pattern of an open-topped five-sided box from W x D x H; one closed Cut outline plus Score folds; optional glue flanges on the side walls that fold in against the front/back walls; dimensions are outside size, no fold allowance for thickness), `fingerbox.ts` (Tools > Finger-joint box: the panels of a box with interlocking square fingers from outside W x D x H, thickness and target finger width; each panel is its full footprint with t-deep notches, the base/lid own the corner cubes and walls alternate odd cells with the base and along vertical corners; the finger count per edge is odd and the width is adjusted to fit; back = front and right = left; all Cut, no kerf allowance; `tests/fingerbox.test.ts` checks every point of the shell is in exactly one panel), `workspace.ts` (file tabs, pure: `Workspace` holds the open files; the tab showing lives in `Doc` and the server panel, the others are parked `DocSnapshot`s with their own undo history and a `FileMeta` (draft id, origin, saved fingerprint, local copy, source file); `matches`/`find` stop one file opening twice; `duplicate`; `fileKey`/`isDirty`; `snapshotOf`/`pasteIntoSnapshot` for moving shapes between tabs), `dialog.ts` (native <dialog> parameter form; every dialog can be dragged by its title (`makeDraggable`); `onChange` gives a **live preview**: called with the values on every change (null when they are unusable or the dialog closes) and its returned text is shown in the dialog; such a dialog has no dimmed backdrop and starts at the right-hand side. Linear repeat and Circular array use it: `previewPattern` in `main.ts` draws the copies dashed orange (`patternPreview`, up to 3000 shapes) and says how many will be added or what is wrong), `presets.ts` (placeholder material presets + per-laser resolution), `clipboard.ts` (strict parse of pasted Kerf clips; copy/paste uses the browser clipboard events), `align.ts` (align/distribute; groups are one unit), `boolean.ts` (union/intersect/subtract via paper.js; Bezier results are fitted back to true arcs, preferring the input circles; groups and text are compound operands), `gizmo.ts` (gimbal handle layout, hit-testing and drag maths; matrices are set from drag-start snapshots), `text.ts` (text to paths: DejaVu outline fonts via opentype.js laid out glyph by glyph, Hershey single-line fonts; live text objects are `textId` contours in `Doc`, regenerated by `retext`, flattened by `convertText`), `offset.ts` (Offset tool: parallel copies of selected shapes and lines at a distance; closed shapes go outside/inside/both, open lines left/right/both of the way they run; Clipper (`clipper-lib`, Boost licence) does the geometry on a finely flattened outline and the result is turned back into true lines and arcs by matching points to the circles an offset must lie on (concentric arcs, and arcs about the old corners for round corners); long flattened curves are simplified to within 4 micrometres; the Options panel shows a dashed live preview and can keep or replace the original), `spline.ts` (Spline tool: a smooth curve through clicked points as cubic Beziers, centripetal Catmull-Rom so it never loops or overshoots; `DocObject.spline` remembers the through-points so the Nodes tool drags/inserts/deletes points and the curve is re-fitted; any other edit calls `convertText` which drops the spec, leaving a plain cubic path; splines go to the job as ordinary `cubic` segments, and are not restored as splines when a saved file is reopened), `dimensions.ts` (dimension annotations: linear aligned/horizontal/vertical and radial diameter/radius; pure geometry for drawing, picking and labels; they live in `Doc.state.dimensions`, are drawn teal, selectable (Delete removes), toggled with the Dimensions checkbox, and are **annotations only: never in DXF/SVG export, never in the job's objects or G-code**; they are saved with the job in the schema's `dimensions` array and come back when a file is reopened), `snap.ts` (snap planner; object snaps beat the grid), `ruler.ts` (ruler ticks, measure), `bounds.ts` (out-of-bed check, canSubmit), `status.ts` (footer text), `trim.ts` (trim: pure planner, bakes placement into the kept paths), `anchor.ts` (3x3 anchor, numeric X/Y position and W/H resize, scale % and rotate, all about the anchor), `doc.ts` (objects + undo/redo), `export.ts` (DXF/SVG), `dxf-import.ts` (LINE, ARC, CIRCLE, LWPOLYLINE, POLYLINE, SPLINE), `main.ts` (UI).
- **Size check on import** (`importscale.ts`, `importDXF` in `main.ts`): after the units are applied, a model whose longest side is **under 10 mm or over 400 mm (40 cm)** opens a "Check the size of this model" dialog before anything is added. It says the size, whether the file gave its units (`$INSUNITS`) or was read as cm, and offers three radio choices, each with the size it would give: *Keep it as it is*, *mm → cm: make it 10 times smaller* (÷10) and *cm → mm: make it 10 times bigger* (×10). The one that points the right way and lands in range is preselected and marked "looks right" (`suggestedChoice`); Cancel imports nothing. Files in range import without a dialog. The dialog uses the new `radio` field type in `dialog.ts`.
- Import converts, normalises and auto-joins touching entities per layer (units -> mm; a file with no `$INSUNITS` is assumed to be centimetres, the Onshape default; bbox bottom-left -> 0,0). Dedupe/overlap-merge clean-up is Server work (join is done here too, so the editor works standalone). Unsupported entities (TEXT, HATCH, ELLIPSE...) are counted and reported, not imported.
- Groups are a `group` id on `DocObject` (one level; grouping again merges). Selection and moves always go through `Doc.expand()` so group members act together. The 1 cm grid is drawn by `drawGrid` in `main.ts` (toggle in the toolbar).

## Server (pupil sign-in, files)
**Everybody signs in with DINO** (`sso.ts`, Authorization Code + PKCE); there is no class code + PIN form, no pasted-token sign-in and no PINs any more, and nothing is stored in localStorage (the old `kerf.session` key is cleared). The roles come from DINO: pupil, teacher, admin and **technician** (runs the Station pages only). On the Admin site, a class's **Pupils** (`classesui.ts`) creates classes and adds pupils by their DINO IDs (paste a list) and removes them. Sign-in is on a full-screen gate (`#gate` in `index.html`); a small "work without signing in" link keeps the Editor usable offline (Send then asks to sign in). `server.ts` is the API client (token + address in localStorage; errors become readable `ServerError`s), `job.ts` converts the page to a job document and back (`buildJob` / `fromJobObjects`; tab fractions <-> `atLengthMm`; arc `ccw` <-> `clockwise`; groups and live text are not stored, text reopens as plain paths), `serverui.ts` has the top-bar buttons and the gate: **autosave** (there is no Save button: see "Autosave and kept tabs" below), **Send for cutting** (save, then submit; asks where to place it: at the laser head with an anchor, or exactly on the bed), **My files** (Open a draft to keep working, Open a copy of anything already sent, Send, Cancel; shown automatically after sign-in if the pupil has files). A fingerprint of the page (`fileKey`) detects unsaved changes (`beforeunload`; closing a dirty tab and signing out with something unsaved ask first). Sign-out empties the page and the undo history (`Doc.reset`) so the next pupil never sees it. On sign-in the material list becomes the server's presets (`presetStore` in `presets.ts`). Served by the server the address is blank (same origin); under `npm run dev` enter the server address and set `KERF_CORS_ORIGINS=http://localhost:5173` on the server. 
**Station mode and the teacher screen** (`stationui.ts`, pure helpers in `stationlogic.ts`): signing in with a *station* token (`kerf-admin create-token --role station --id station-1`) opens a full-screen Station view instead of the design Editor: the queue (with "Next" highlighted for this laser), the next job's outline preview, material and size, then **Frame** (laser off, trace the outline) -> tick "I have loaded <material>" -> **Start cutting**; while cutting it shows progress, elapsed/estimated time, Pause/Resume/Stop and the camera picture if there is one; "Not ready: let the next person go" defers the ticket. It polls every 2 s and only offers what the server will accept (`stepState`); the server still enforces everything. A *teacher* or *admin* token has no Queue or Classes buttons in the Editor any more: the Editor shows an **Admin site** link instead (see below). Try it all without a laser using `python -m kerf_server.devtools.fake_cutter`.

## Activities and feedback
A class's teacher sets **activities** (title, instructions, optional suggested material and due date, visible/hidden, ordered). Pupils see them under **Activities** in the top bar: *Start working* sets the current activity (shown in the top bar with a x to stop; files saved while it is current carry its `activityId`) and opens the file already made for it, *Hand in for review* saves the page then submits the latest file; status chips: Not started / Working / Handed in / Please improve / Complete; feedback from the teacher is shown there. Teachers (Admin site): **Classes** -> *Activities…* / *Progress…* (or the Activities page): manage activities (new, edit, publish/hide, reorder, duplicate, archive, and *Copy from another class…*: tick which activities, optionally keep due dates / publish at once; copies start hidden with no due date; pupils' work and feedback are never copied) and a pupils x activities **Progress** grid; click a cell to see the pupil's file (outline preview, *Open in the Editor* as a copy) and give feedback: comment, ask to improve (pupil sees "Please improve" and can resubmit) or mark complete. Code: `activitiesui.ts` (+ `dom.ts` helpers, API in `server.ts`).

## Fonts
`public/fonts/` holds DejaVu (free licence, see DEJAVU-LICENSE.txt). `src/fonts/hershey.json` is a subset of the Hershey single-line fonts via the MIT-licensed hersheytext package (HERSHEYTEXT-LICENSE.txt). opentype.js 2.x has no types (`src/opentype.d.ts`) and throws on some GSUB tables, so never call `font.getPath(text)`; lay out per glyph.

## Layout (LightBurn-style)
`index.html` + `src/style.css`: two-row top bar (row 1: **Files** menu = Import DXF / Export DXF / Export SVG, **Cutting** menu = Send for cutting, **Tools** menu, then on the right the save status, the current activity and the **signed-in person's menu** = My files, Activities (pupils), Admin site (teachers/admins), Sign out; row 2: undo/redo, copy/paste/duplicate/delete, grid/dimensions/snap, warnings, bed size). All menus share one handler in `main.ts` (`.menu` > `.menu-btn` + `.menu-list`; one open at a time; Esc, an outside click or choosing an item closes it). Signed out, the person button reads "Sign in" and is the action itself (`data-direct`). The button shows the person's **name** (`personLabel`): after sign-in `sendProfile` (`POST /auth/profile`) returns the DINO display name, which is kept on `Session.name` in memory only (never written to any storage; the page redraws on the `kerf-profile` event) and is cut short by CSS if long. If DINO cannot say, a shortened ID is shown. An email is never fetched or shown: the server never returns one), left two-column tool palette holding EVERY tool and action as an icon button (draw, edit, boolean, arrange, align, repeat; icons live in `src/icons.ts` and are injected as an SVG sprite, `tests/icons.test.ts` checks every icon is used, every button has a tooltip and aria-label), canvas centre, right sidebar (Properties, Options, Cuts / Layers), bottom bar (Cut/Score layer chips + material picker with locked settings), footer (selection size, notices, cursor). Element ids are the contract with `main.ts`: keep them when moving things around.
- **Bed size, not laser** (`bedsize.ts`, the Bed dropdown): a pupil does not know which laser will cut their file, so there is no laser picker. The bed starts at the largest size every laser can cut (`commonBed` of the machine profiles), the dropdown lists each laser's real size, and *Custom size…* takes any width/height (50 to 2000 mm, remembered in localStorage `kerf.bed`). Sending is blocked if part is off the bed, or if the design is bigger than every laser's bed. Settings are the material's base settings (`resolvePreset(preset, null)`: no per-laser overrides, no "untested" flag). The submitted job has `station: null`; it waits under **Waiting for approval** on the Admin site (the Overview flags it), and the teacher approves it and picks the laser (or leaves Any laser). The server's per-laser fit warnings show on that row. The **design size** (the extent of what is cut or scored, not the bed) is in `estimate.extentMm` and `QueueEntry.extentMm` (shared 0.2.15, set by the G-code step before kerf compensation) and is shown on the approval row, the queue rows, the station queue and the pupil's "Sent" receipt via `sizeText` (older files fall back to `sizeOf(objects)`), so the teacher can pick a laser it fits.
- **Open paths** (`openpaths.ts`): a shape on the Cut layer that is not closed cuts a line, not a part. This is a **warning, not a block**: *Send for cutting* (and *Send for cutting* in My files) shows "Open paths on the Cut layer" (the default answer is "Go back and check"), marks the open ends on the drawing, and sends only if the pupil chooses "Send anyway", which passes `acceptOpenPaths` to `POST /jobs/{id}/submit` (shared 0.2.29); the server keeps answering `422 open_cut_path` without it (`KERF_OPEN_CUT_PATHS=block`, so a client that never asks cannot slip one through) and accepts the file with a warning with it. The **Check open paths** tool (palette button, `act-openpaths`) is a toggle: a large solid red dot with a white ring at both free ends of every open path on the Cut layer, and a small red ring on open Score lines (which are normal); the Ignore layer is skipped; it follows edits while on, and says how many it found. `confirmDialog` in `dialog.ts` is the two-button warning (safe answer focused).
- **Ignore layer** (`LayerType` "ignore", dark grey `#4b5563`, third chip in the bottom bar and a row in the layers table): for guides and notes. It is saved in the job (shared 0.2.16) so it reopens, but it may sit off the bed, does not count as something to send (`canSubmit`/`outOfBounds`), is left out of DXF/SVG export (`forLaser` in `export.ts`), of the station preview and of `sizeOf`; a DXF layer whose name contains "ignore" imports as Ignore. The Server skips it (`gcode.cuttable`) and refuses a job of only Ignore shapes.
- **File tabs** (strip under the top bar, `#filetabs`; logic in `workspace.ts`, wiring in `main.ts` "file tabs", hooks in `serverui.ts`): several files open at once, each with its own shapes, material, undo history and server draft. A file is never open twice: opening a draft from *My files* (or an activity) that is already in a tab switches to that tab (`ctx.tabs.show`); opening a sent file as a copy twice finds the same copy tab; once a copy is saved it is its own file. **Duplicate tab** makes a second file (new, unsaved, no server id; it is saved as a separate job). **Move shapes to tab…** (also in Tools) moves or copies the selection, with place, layer and groups, to a new tab or another open tab, to split a big import into files of their own. Tabs have short names that never change by themselves: "Untitled", "Untitled 2"…, "<name> copy", "Design 16 Oct 14:02" for a file opened from the server (`designName`; an activity's file is named after the activity), or what the pupil renamed them (double-click; names are not saved). The long job id is only in the tab's tooltip; a dot marks unsaved changes; closing a dirty tab, signing out and leaving the page ask first. Sign-out closes every tab (`Workspace.reset`). Tabs live in memory only: reloading the page loses unsaved ones (as before). Not to be confused with `tabs.ts`, which is the *bridges* on a cut outline.
- The layer chips set the layer for NEW shapes (`activeLayer`) and move the current selection onto that layer.
- `presets.ts` holds PLACEHOLDER presets in the shape of `shared/preset.schema.json` (a test validates them against it); `resolvePreset` applies per-laser overrides and flags untested lasers. The chosen preset id lives in `Doc.state.materialId`. Pupils see the settings locked.

- Palette actions disable themselves when they cannot apply (`refreshActions` in `main.ts`): booleans/group need 2+ shapes, space needs 3+, etc.

- **Import pupils' files** (teacher/admin, Files menu, `consolidate.ts` + `consolidateui.ts`; **paid tier**: shown only when `isPaid`, i.e. the school has the laser, because it works from the queue): pick a **DINO class** (`GET /groups`, shared 0.2.30; the teacher's own DINO classes with their pupil IDs), see its files waiting in the queue (`submitted`/`approved`, filtered on the client by those pupil IDs from `GET /jobs?status=`), tick the ones to bring in. Each file becomes ONE group in the open file (`doc.state.nextGroup++`), laid out in rows on the bed by `planLayout` (8 mm gap, 10 mm margin; says so if they do not fit rather than refusing), keeping per-shape settings and tabs. Optional pupil-name label above each file on the **Ignore** layer (geometry only, never cut). Warns when the chosen files use different materials; an empty document takes the files' material when they agree. The files stay in the queue.

- **Trace image** (`imagetrace.ts` pure + Potrace call, `imagetraceui.ts` dialog, wiring "trace a picture" in `main.ts`): paste a picture (a screenshot or "copy image": the `paste` handler looks for an image file before text), drop one on the canvas, or Files > Trace image. The picture is shrunk to at most 1200 px, flattened onto white, thresholded to black/white (`toBlackWhite`), and traced by **Potrace** (`esm-potrace-wasm`, WASM inlined in its JS and loaded as its own chunk on first use; runs in the browser, **the picture is never uploaded**, only the traced paths are saved). Potrace writes paths in tenths of a pixel, Y already up, from the picture's bottom-left (`POTRACE_UNITS_PER_PX`), which `toDesign` scales to mm. The dialog has threshold, trace dark/light, width (height follows), speck size, corners (sharp/normal/smooth = Potrace `alphamax`), smallest shape to keep (`dropSmall`, default 1 mm) and Cut or Score; a dashed live preview (the same `patternPreview` as the pattern tools, centred on the bed) updates 150 ms after the last change. The result is one group of closed cubic paths (holes included), selected. Notices explain empty results, a mostly-traced picture (try Invert), too many shapes, and that islands need bridges. Photos do not trace well (no edge-detection mode yet). **Potrace is GPL-2.0**: fine for internal school use, a licence question only if the Editor is ever distributed. Tests: `tests/imagetrace.test.ts` (the Potrace call itself needs a browser: checked by hand with a ring and a rectangle).

## Camera alignment (Station mode)
At the laser PC the pupil lines the design up on the **live camera picture** (`alignui.ts`): press *Line up on the camera picture*, drag the outline onto the material, turn it with the round knob (or the arrow and turn buttons / arrow keys), then *Confirm position*. Confirm calls `POST /jobs/{id}/placement` with a rigid matrix (move and turn only); the job becomes `absolute`, the old Frame is cleared, and the pupil presses **Frame** to double-check (the picture is fisheye-curved near the edges).
- The picture and the outline share ONE svg whose units are camera pixels, so they stay registered. The camera -> bed mapping is a homography (`homography.ts`: `solveHomography`, `applyH`, `invertH`); the maths of placing and dragging is in `alignlogic.ts` (pure, tested in `tests/align.test.ts`). The page re-attaches the alignment's own element on each poll instead of rebuilding it, and `stationui.render()` does nothing while an alignment is open, so a drag is never interrupted. `camerafeed.ts` refreshes the picture (about every 0.7 s; the brief's 5 to 10 fps WebSocket feed can replace it).
- **Calibration** is done by a teacher **at the laser PC, from Station mode** (header button *Calibrate camera*, `calibrateui.ts`). Calibrating changes what every pupil sees, so the dialog asks for a *teacher token*: it is used for that dialog only (to make the marks job, run it with `skipQueue`, and `PUT` the calibration) and never stored; the station token itself cannot change a calibration. Two ways: **Cut test squares** (use this when the bed is bigger than the camera sees, which is the usual case): the laser cuts 1 or 4 squares of known size at a known bed position on a scrap (`POST /stations/{id}/calibration-marks`: a job pinned to that laser, approved, Score by default; the dialog frames it, waits for Idle, starts it, waits for Done, and cancels it if anything fails), then the teacher clicks each square's corners in the live picture; or **Bed corners** when the whole bed is in view. Many points are fitted by least squares (`solveHomographyLS`), so spread the squares over what the camera sees: the map is accurate inside the marks and only extrapolates outside them. The dialog shows the typical and worst miss in mm and an orange 50 mm grid preview; markers can be dragged. This is the approximate first version (a flat map, no lens correction); the brief's accurate version (lens calibration done by the Cutter) can replace the stored matrix without changing the API. Without a calibration (`StationInfo.calibrated` false) Station mode says so and the old flow (head to the material, Frame) still works. The Admin site's Lasers page only shows whether each camera is calibrated.
- `python -m kerf_server.devtools.fake_cutter` sends a test picture of a 400 x 400 mm bed (corners at camera pixels (110,430), (540,425), (500,40), (150,45)) so all of this can be tried without a camera.

## Stations page (Admin site): stations and Cutter software

## A failed save is never a lost design (`localdrafts.ts`, `serverui.ts`)
If Save or Send cannot reach or satisfy the server (network down, signed out, schema problem, anything), the design is kept in this browser's local storage (`kerf.localdrafts`: the newest ten, the pupil ID and job, never a name, never sent anywhere) and the dialog says so, with the server's own list of problems (`explain`). **My files** then has an *On this computer (not on the server yet)* section: Open (loads it; a later Save to the server removes the local copy), Save to the server, Delete. It is also shown automatically after sign-in when a pupil has copies waiting. If the browser will not store it either, the dialog says to use Export DXF.

## Autosave and kept tabs (`serverui.ts`, `main.ts`, `workspace.ts` Mirror)
There is no Save button. Every change is saved twice:
- **To the server**, about 1.5 s after the last change (`noteChange` -> `autosave` -> `saveCurrent`): creates the draft the first time (not for an empty page), then PUTs it. Saves of one file are chained, and each writes to the `FileMeta` it started on, so switching tabs mid-save is safe. Leaving a tab, new tab, duplicate, sign-out and `pagehide` flush at once (`flushNow`); Ctrl/Cmd+S just says so. A failure shows "Not on the server yet: kept on this computer, trying again" and retries after 5 s, doubling to 60 s; a 401 drops the session. Status text is `#srv-save-state`. Applies to every signed-in role except stations. A tab changed in the background by *Move shapes to tab* saves when it is next shown.
- **To this browser**, within about 0.3 s (`persistTabs`): the whole workspace (every tab's full document state, so groups, text and splines survive, plus its server id and saved fingerprint, but not undo history) under `kerf.workspace.<pupil ID | "offline">` (`mirrorKey`; IDs only, never names). On a refresh, on signing in again, and when "work without signing in" is chosen, `restoreTabs` brings the tabs back (it replaces an untouched page, or adds them after work already open without duplicating a file already open). Nothing is written until the restore has been tried (`mirrorOwner`), so a refresh can never overwrite saved tabs with an empty page; an empty workspace removes the entry. Sign-out clears the screen (the next pupil sees nothing) but **keeps** the entry for that pupil, so their tabs return when they sign in again on that computer. If the server cannot be reached when the page loads, the tabs still come back. If the browser's storage is full the status says so (`setLocalOk`). Damaged entries are ignored (`parseMirror` validates every shape). Tabs on another computer come from the server instead (*My files*).
- **My files has two tabs**: *On the server* (the pupil's jobs) and *On this computer*, which lists (1) the files open in tabs now (Show), (2) **Closed tabs**: closing a tab keeps its whole file in this browser (`addClosed`, key `kerf.closed.<pupil ID>`, newest 20, one entry per server file, empty files are not kept; Open puts it back in a tab, or switches to it if that server file is already open; Delete removes only the local copy) and (3) copies kept because a *Send* failed (`localdrafts.ts`). Each list is read with the signed-in pupil's own ID as the key (`ctx.tabs.listClosed/openClosed/deleteClosed` refuse any other owner), so a pupil only ever sees and opens files made under their own ID; the server enforces the same for its list.

## Files you can name, rename and delete; tabs that follow you (shared 0.2.25)
- **Names.** A file has an optional `name` (the tab's name, up to 60 characters). Autosave sends it (`ctx.fileName`: null while the tab is still "Untitled"/"Untitled 2"); renaming a tab (double-click) or a file in *My files* (**Rename**) calls `PUT /jobs/{id}/name` and keeps the open tab in step (`ctx.tabs.setName`). *My files* shows the name, or "Design 16 Oct 14:02" (`designName`) for a file without one; the job id is only the row's tooltip.
- **Delete.** *My files* has **Delete** for drafts and cancelled or failed files (confirm first; the open tab for it closes without keeping a copy: `dropFileTab`). The server refuses with a reason for a file that is waiting or on a laser (cancel it first), a finished cut (kept as the pupil's record) and work handed in for an activity. Only the owner can rename or delete (a teacher cannot, even though they can see a pupil's file).
- **Open tabs on every browser.** The server keeps, per person, the files they have open (`GET`/`PUT /workspace`: tab order, names, the one showing). `pushWorkspace` (from `persistTabs`, about 0.3 s after any change, retried after 10 s if it fails) sends only tabs that are saved files; nothing is sent until the restore has run (`restoring`/`mirrorOwner`). On sign-in or refresh `restoreTabs` asks the server and merges with this browser's copy (`remotetabs.ts` `mergeRemoteTabs`): a file edited here and not yet saved keeps this browser's copy, a file that matches the server's keeps this browser's richer copy (groups and live text are not in the job format), a file changed on another browser or new here comes from the server, a file closed or deleted elsewhere drops out, and work only this browser has is never dropped. It is read when you sign in or reload, not live: a tab opened on another browser appears here at the next sign-in or refresh. Only files that are still drafts become tabs.

## Sending again replaces the old file
The Send dialog warns when the pupil already has a file waiting ("sending this replaces it, and you go to the back of the queue"), and the confirmation says which file was replaced (`Receipt.replaced`). The server does the replacing (see `server/CLAUDE.md`); the Editor only tells the pupil.

## Sign in with DINO (planner-004)
`sso.ts` (pure, tested in `tests/sso.test.ts`): `fetchAuthConfig` reads `GET /auth/config` (an older server or any failure means class code + PIN only); `beginSignIn` makes a PKCE S256 verifier and a state, keeps them in sessionStorage and sends the browser to DINO; DINO returns to a **fixed address** (`redirectUriFor(app, loc)`: `<origin>/` for the Editor, `<origin>/admin/` for Admin, wherever the sign-in started; register exactly those redirect URIs; the server forwards `/?code=` to `/editor/`), `finishSignIn` checks `state`, trades the code at the token URL, and asks `/auth/me` who it is. The access token (a ~15 min JWT) is only in `Session.token` in memory; `Session.sso = true` makes `saveSession` skip localStorage. The rotating refresh token is in sessionStorage (`kerf.sso.refresh.<app>`) so a reload of the tab restores the sign-in (`restoreSignIn`) and closing the tab ends it. `Renewer` renews a minute before expiry and updates `session.token` in place (offline: retries in 15 s; DINO refusing: back to the sign-in page). Sign-out calls `endSignIn` (revoke, best effort). The Editor gate shows a "Sign in with DINO" button unless the server is `pins`-only, and hides the class code + PIN form when it is `planner`-only (laser stations still use a token). Admin does the same and accepts only teacher/admin. After sign-in `sendProfile` (`POST /auth/profile`) asks the server to remember the person's DINO display name; staff then see it instead of an ID (`pupilLabel(id, name)` on the Station queue, Admin queue, Pupils page, class list and progress grid). The browser stores no name; emails are never used.

## Technicians and Station pages
A **technician** signing in to the Admin site sees only **Station pages** (`stationPages` in `admin/pages.ts`): one *Open station page* link per laser, `/editor/?station=<id>`. Admins also have that page; teachers do not. Following the link, the Editor remembers the laser in sessionStorage (`kerf.station`, so it survives the trip to DINO and back) and `serverui.enterRole` opens the full-screen Station page (`openStation(session, signOut, {stationId, onOtherStation})`) for it. A technician who arrives without a link gets the laser picker (`openStationPicker`) and never sees the design Editor. The Station page runs on the person's own DINO session (the server accepts a technician where it accepts a station token); *Calibrate camera* no longer asks for a teacher token, it uses that session (technician, teacher or admin). The Cutter keeps its own station token. The Admin site's *Station tokens* page (admin) makes and revokes those; it can no longer make teacher or admin tokens.

Station page, picking and rejecting: a technician (or teacher/admin) clicks any *takeable* file in the queue (approved, not meant for another laser, not being set up on another; `takeable` in `stationui.ts`) and the right-hand panel shows it ("Selected" instead of "Next", with a note that it jumps the queue and a "Back to the next file" link). Frame, Line up (placement) and Start send `skipQueue` when the file is not the one that is next (`skip`/`queueSkip`); the server allows that for technician, teacher and admin only. **Reject with a note…** asks for a note and calls `POST /jobs/{id}/reject`; a technician may only reject an *approved* (queued) file, and the pupil sees "Rejected at the laser: <note>" as the file's status reason.

**Disconnect Cutter**: a button on the Station page header (technician, teacher, admin; hidden while cutting) and on each Admin *Stations* card calls `POST /stations/{id}/disconnect` after a confirm; the Cutter stays disconnected until started again on its PC.

**Taking over**: on a laser's Station page every waiting file is clickable, including ones meant for (or being set up on) another laser. Those show "This file is for station-N" with **Take over for station-M** (`POST /jobs/{id}/take`) and Reject; after taking over, the normal Frame/Start flow applies.

**Auto-approve** (Admin site, Queue page): a checkbox above the queue (`setAutoApprove`, `PATCH /school`), on by default. While on, new files skip *Waiting for approval* and go straight to the queue; files already waiting are not affected.

**Untested material at the laser**: never blocks cutting (test grids are ad hoc). When the material is not in `testedOn` for this laser the Station page shows staff (technician, teacher, admin) a note and an optional **Mark <material> tested on <laser>** link (`markTested`, after a confirm; presets are reloaded).

**Materials page** (Admin site, teachers and admins; `materials` in `admin/pages.ts`, form logic in `materialform.ts`, tested against the preset schema): a table of the school's materials (kerf, Cut and Score power/speed/passes/air, which lasers have their own settings, which are test-gridded). **New material** / **Edit…** / **Copy…** (`materialFields`, `presetFromForm`; a new id is made from the name and thickness, e.g. `mdf-3mm`; an edit keeps per-laser settings, tested lasers and dotted-line lengths) and **On one laser…** (`overrideFields`, `presetWithOverride`: blank means "same as usual", emptying every field removes the laser's own settings, plus the test-gridded flag). Saves with `POST /presets` / `PUT /presets/{id}`; the server makes every edit a new version, so files already sent keep theirs. **Delete** hides a material from the catalogue (old files keep it; see below).

**Queue page tabs** (Admin site): **Queue** (auto-approve switch + `mountQueue`) and **Processed files** (`mountProcessed` in `admin/pages.ts`: the newest 200 done/failed/cancelled files with their result and reason, refreshed every 10 s; **Back to the queue** calls `requeueJob`). The chosen tab is kept in sessionStorage (`kerf.admin.queueTab`). In the queue, waiting and queued files have **Material…** (`changeJobPreset`: pick another material; the file keeps its place) and show the material's name. The Materials page has **Delete** (`deletePreset`; refused while queued files use it).

**Free and paid schools** (shared 0.2.32): the session carries `plan`, `siteAdmin` and `schoolCode` from `/auth/me` (`sso.ts`). `isPaid(session)` (`server.ts`) hides *Send for cutting* (menu and My files) and pupils' *Activities* for a free school.
