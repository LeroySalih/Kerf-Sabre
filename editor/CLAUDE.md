# editor/ (BISAK Kerf Editor)
TypeScript PWA for Chrome/Edge desktop. paper.js for geometry, opentype.js for text. Internal units mm; Design/Bed/Screen/Camera spaces per brief section 5; Bed→Screen conversion lives in ONE function. Edits change object matrices, never source geometry. Export DXF/SVG must work standalone. Does not talk to hardware directly (no Web Serial).

## Commands (run from `editor/`)
- `npm install`, `npm run dev` (Vite dev server), `npm run build` (typecheck + bundle), `npm test` (vitest), `npm run typecheck`.
- Machine profiles are imported from `../shared/machine-profiles` at build time (`src/machine.ts`).
- `src/coords.ts` holds Bed<->Screen conversion; do not convert elsewhere. `public/sw.js` is the offline app-shell cache.

## Modules
- `geometry.ts` (segments/matrices/shapes), `select.ts` (box select), `tabs.ts` (tabs/bridges: stored on `DocObject.tabs` as fractions along the closed Cut outline plus a width in mm; `splitByTabs` turns them into the open pieces the laser cuts, applied in DXF/SVG export and, later, G-code), `repair.ts` (join loose segments into paths with a bucketed tolerance match, close, explode, and node move/insert/delete; DXF import auto-joins per layer), `fillet.ts` (also `roundedRectangle`; corner radius/chamfer of straight-line corners as true arcs; clamps to half of each edge), `icons.ts` (tool icon set + sprite), `arrays.ts` (linear repeat, circular array, mirror), `testgrid.ts` (material test grid and kerf coupon generators; cells record per-shape power/speed in `DocObject.settings`), `boxnet.ts` (Tools > Box net: flat pattern of an open-topped five-sided box from W x D x H; one closed Cut outline plus Score folds; optional glue flanges on the side walls that fold in against the front/back walls; dimensions are outside size, no fold allowance for thickness), `fingerbox.ts` (Tools > Finger-joint box: the panels of a box with interlocking square fingers from outside W x D x H, thickness and target finger width; each panel is its full footprint with t-deep notches, the base/lid own the corner cubes and walls alternate odd cells with the base and along vertical corners; the finger count per edge is odd and the width is adjusted to fit; back = front and right = left; all Cut, no kerf allowance; `tests/fingerbox.test.ts` checks every point of the shell is in exactly one panel), `workspace.ts` (file tabs, pure: `Workspace` holds the open files; the tab showing lives in `Doc` and the server panel, the others are parked `DocSnapshot`s with their own undo history and a `FileMeta` (draft id, origin, saved fingerprint, local copy, source file); `matches`/`find` stop one file opening twice; `duplicate`; `fileKey`/`isDirty`; `snapshotOf`/`pasteIntoSnapshot` for moving shapes between tabs), `dialog.ts` (native <dialog> parameter form), `presets.ts` (placeholder material presets + per-laser resolution), `clipboard.ts` (strict parse of pasted Kerf clips; copy/paste uses the browser clipboard events), `align.ts` (align/distribute; groups are one unit), `boolean.ts` (union/intersect/subtract via paper.js; Bezier results are fitted back to true arcs, preferring the input circles; groups and text are compound operands), `gizmo.ts` (gimbal handle layout, hit-testing and drag maths; matrices are set from drag-start snapshots), `text.ts` (text to paths: DejaVu outline fonts via opentype.js laid out glyph by glyph, Hershey single-line fonts; live text objects are `textId` contours in `Doc`, regenerated by `retext`, flattened by `convertText`), `offset.ts` (Offset tool: parallel copies of selected shapes and lines at a distance; closed shapes go outside/inside/both, open lines left/right/both of the way they run; Clipper (`clipper-lib`, Boost licence) does the geometry on a finely flattened outline and the result is turned back into true lines and arcs by matching points to the circles an offset must lie on (concentric arcs, and arcs about the old corners for round corners); long flattened curves are simplified to within 4 micrometres; the Options panel shows a dashed live preview and can keep or replace the original), `spline.ts` (Spline tool: a smooth curve through clicked points as cubic Beziers, centripetal Catmull-Rom so it never loops or overshoots; `DocObject.spline` remembers the through-points so the Nodes tool drags/inserts/deletes points and the curve is re-fitted; any other edit calls `convertText` which drops the spec, leaving a plain cubic path; splines go to the job as ordinary `cubic` segments, and are not restored as splines when a saved file is reopened), `dimensions.ts` (dimension annotations: linear aligned/horizontal/vertical and radial diameter/radius; pure geometry for drawing, picking and labels; they live in `Doc.state.dimensions`, are drawn teal, selectable (Delete removes), toggled with the Dimensions checkbox, and are **annotations only: never in DXF/SVG export, never in the job's objects or G-code**; they are saved with the job in the schema's `dimensions` array and come back when a file is reopened), `snap.ts` (snap planner; object snaps beat the grid), `ruler.ts` (ruler ticks, measure), `bounds.ts` (out-of-bed check, canSubmit), `status.ts` (footer text), `trim.ts` (trim: pure planner, bakes placement into the kept paths), `anchor.ts` (3x3 anchor, numeric X/Y position and W/H resize, scale % and rotate, all about the anchor), `doc.ts` (objects + undo/redo), `export.ts` (DXF/SVG), `dxf-import.ts` (LINE, ARC, CIRCLE, LWPOLYLINE, POLYLINE, SPLINE), `main.ts` (UI).
- Import converts, normalises and auto-joins touching entities per layer (units -> mm; a file with no `$INSUNITS` is assumed to be centimetres, the Onshape default; bbox bottom-left -> 0,0). Dedupe/overlap-merge clean-up is Server work (join is done here too, so the editor works standalone). Unsupported entities (TEXT, HATCH, ELLIPSE...) are counted and reported, not imported.
- Groups are a `group` id on `DocObject` (one level; grouping again merges). Selection and moves always go through `Doc.expand()` so group members act together. The 1 cm grid is drawn by `drawGrid` in `main.ts` (toggle in the toolbar).

## Server (pupil sign-in, files)
Pupils sign in with **class code + pupil ID + PIN** (`loginWithPin`; the server returns a short-lived token, sign-out revokes it; the class code is remembered, the PIN never is). Teachers and laser stations use the "sign in with a token" link. On the Admin site, a class's **Pupils and PINs** (`classesui.ts`) creates classes, adds pupil IDs (paste a list) and shows each new PIN once with copy/download, resets PINs and removes pupils. Sign-in is on a full-screen gate (`#gate` in `index.html`); a small "work without signing in" link keeps the Editor usable offline (Send then asks to sign in). `server.ts` is the API client (token + address in localStorage; errors become readable `ServerError`s), `job.ts` converts the page to a job document and back (`buildJob` / `fromJobObjects`; tab fractions <-> `atLengthMm`; arc `ccw` <-> `clockwise`; groups and live text are not stored, text reopens as plain paths), `serverui.ts` has the top-bar buttons and the gate: **autosave** (there is no Save button: see "Autosave and kept tabs" below), **Send for cutting** (save, then submit; asks where to place it: at the laser head with an anchor, or exactly on the bed), **My files** (Open a draft to keep working, Open a copy of anything already sent, Send, Cancel; shown automatically after sign-in if the pupil has files). A fingerprint of the page (`fileKey`) detects unsaved changes (`beforeunload`; closing a dirty tab and signing out with something unsaved ask first). Sign-out empties the page and the undo history (`Doc.reset`) so the next pupil never sees it. On sign-in the material list becomes the server's presets (`presetStore` in `presets.ts`). Served by the server the address is blank (same origin); under `npm run dev` enter the server address and set `KERF_CORS_ORIGINS=http://localhost:5173` on the server. 
**Station mode and the teacher screen** (`stationui.ts`, pure helpers in `stationlogic.ts`): signing in with a *station* token (`kerf-admin create-token --role station --id station-1`) opens a full-screen Station view instead of the design Editor: the queue (with "Next" highlighted for this laser), the next job's outline preview, material and size, then **Frame** (laser off, trace the outline) -> tick "I have loaded <material>" -> **Start cutting**; while cutting it shows progress, elapsed/estimated time, Pause/Resume/Stop and the camera picture if there is one; "Not ready: let the next person go" defers the ticket. It polls every 2 s and only offers what the server will accept (`stepState`); the server still enforces everything. A *teacher* or *admin* token has no Queue or Classes buttons in the Editor any more: the Editor shows an **Admin site** link instead (see below). Try it all without a laser using `python -m kerf_server.devtools.fake_cutter`.

## Activities and feedback
A class's teacher sets **activities** (title, instructions, optional suggested material and due date, visible/hidden, ordered). Pupils see them under **Activities** in the top bar: *Start working* sets the current activity (shown in the top bar with a x to stop; files saved while it is current carry its `activityId`) and opens the file already made for it, *Hand in for review* saves the page then submits the latest file; status chips: Not started / Working / Handed in / Please improve / Complete; feedback from the teacher is shown there. Teachers (Admin site): **Classes** -> *Activities…* / *Progress…* (or the Activities page): manage activities (new, edit, publish/hide, reorder, duplicate, archive, and *Copy from another class…*: tick which activities, optionally keep due dates / publish at once; copies start hidden with no due date; pupils' work and feedback are never copied) and a pupils x activities **Progress** grid; click a cell to see the pupil's file (outline preview, *Open in the Editor* as a copy) and give feedback: comment, ask to improve (pupil sees "Please improve" and can resubmit) or mark complete. Code: `activitiesui.ts` (+ `dom.ts` helpers, API in `server.ts`).

## Fonts
`public/fonts/` holds DejaVu (free licence, see DEJAVU-LICENSE.txt). `src/fonts/hershey.json` is a subset of the Hershey single-line fonts via the MIT-licensed hersheytext package (HERSHEYTEXT-LICENSE.txt). opentype.js 2.x has no types (`src/opentype.d.ts`) and throws on some GSUB tables, so never call `font.getPath(text)`; lay out per glyph.

## Layout (LightBurn-style)
`index.html` + `src/style.css`: top bar (file, history, edit, view, Tools menu, bed size), left two-column tool palette holding EVERY tool and action as an icon button (draw, edit, boolean, arrange, align, repeat; icons live in `src/icons.ts` and are injected as an SVG sprite, `tests/icons.test.ts` checks every icon is used, every button has a tooltip and aria-label), canvas centre, right sidebar (Properties, Options, Cuts / Layers), bottom bar (Cut/Score layer chips + material picker with locked settings), footer (selection size, notices, cursor). Element ids are the contract with `main.ts`: keep them when moving things around.
- **Bed size, not laser** (`bedsize.ts`, the Bed dropdown): a pupil does not know which laser will cut their file, so there is no laser picker. The bed starts at the largest size every laser can cut (`commonBed` of the machine profiles), the dropdown lists each laser's real size, and *Custom size…* takes any width/height (50 to 2000 mm, remembered in localStorage `kerf.bed`). Sending is blocked if part is off the bed, or if the design is bigger than every laser's bed. Settings are the material's base settings (`resolvePreset(preset, null)`: no per-laser overrides, no "untested" flag). The submitted job has `station: null`; it waits under **Waiting for approval** on the Admin site (the Overview flags it), and the teacher approves it and picks the laser (or leaves Any laser). The server's per-laser fit warnings show on that row. The **design size** (the extent of what is cut or scored, not the bed) is in `estimate.extentMm` and `QueueEntry.extentMm` (shared 0.2.15, set by the G-code step before kerf compensation) and is shown on the approval row, the queue rows, the station queue and the pupil's "Sent" receipt via `sizeText` (older files fall back to `sizeOf(objects)`), so the teacher can pick a laser it fits.
- **Ignore layer** (`LayerType` "ignore", dark grey `#4b5563`, third chip in the bottom bar and a row in the layers table): for guides and notes. It is saved in the job (shared 0.2.16) so it reopens, but it may sit off the bed, does not count as something to send (`canSubmit`/`outOfBounds`), is left out of DXF/SVG export (`forLaser` in `export.ts`), of the station preview and of `sizeOf`; a DXF layer whose name contains "ignore" imports as Ignore. The Server skips it (`gcode.cuttable`) and refuses a job of only Ignore shapes.
- **File tabs** (strip under the top bar, `#filetabs`; logic in `workspace.ts`, wiring in `main.ts` "file tabs", hooks in `serverui.ts`): several files open at once, each with its own shapes, material, undo history and server draft. A file is never open twice: opening a draft from *My files* (or an activity) that is already in a tab switches to that tab (`ctx.tabs.show`); opening a sent file as a copy twice finds the same copy tab; once a copy is saved it is its own file. **Duplicate tab** makes a second file (new, unsaved, no server id; it is saved as a separate job). **Move shapes to tab…** (also in Tools) moves or copies the selection, with place, layer and groups, to a new tab or another open tab, to split a big import into files of their own. Tabs are named after their server file (`job-…`), "Untitled", or what the pupil renamed them (double-click; names are not saved); a dot marks unsaved changes; closing a dirty tab, signing out and leaving the page ask first. Sign-out closes every tab (`Workspace.reset`). Tabs live in memory only: reloading the page loses unsaved ones (as before). Not to be confused with `tabs.ts`, which is the *bridges* on a cut outline.
- The layer chips set the layer for NEW shapes (`activeLayer`) and move the current selection onto that layer.
- `presets.ts` holds PLACEHOLDER presets in the shape of `shared/preset.schema.json` (a test validates them against it); `resolvePreset` applies per-laser overrides and flags untested lasers. The chosen preset id lives in `Doc.state.materialId`. Pupils see the settings locked.

- Palette actions disable themselves when they cannot apply (`refreshActions` in `main.ts`): booleans/group need 2+ shapes, space needs 3+, etc.

## Admin site (`admin/index.html`, `src/admin/`)
A second Vite page at **/admin/** (built into `dist/admin/`, served by the Server next to the Editor). For teachers, school admins and the platform owner; pupils and laser stations are turned away. Sign in with a token (kept under its own localStorage key, `kerf.admin.session`). `main.ts` is the shell (sign-in, nav, school name), `pages.ts` the pages, `admin.css` the layout (it also loads the Editor's `style.css` for dialogs, chips and tables).
- Teacher / admin pages: **Overview** (waiting files, queue, stations online, classes, pupils; refreshes), **Classes** (new class, per-class approval: "A teacher approves each file" / "Straight to the queue", Pupils and PINs, Activities, Progress), **Pupils** (all pupils by class: new PIN, remove), **Activities** (every class's activities with progress counts; Manage opens the existing class-work dialog), **Queue** (`mountQueue` in `stationui.ts`: approve/reject, reorder, cancel; refreshes), **Stations** (add, edit, delete, status, pause/resume/stop, Cutter software). Admin adds **Staff** (teachers, admins and station tokens, shown once; revoke). The platform owner sees only **Schools** (create a school and its first admin; the token is shown once).
- Everything is the school of the signed-in token: the server filters, the site never asks for a school. The Editor shows an **Admin site** link to teachers and admins (and sends a platform token straight there); *My files* is for pupils only.
- Pupil files are looked at as a preview here (no "Open in the Editor" any more).

## Camera alignment (Station mode)
At the laser PC the pupil lines the design up on the **live camera picture** (`alignui.ts`): press *Line up on the camera picture*, drag the outline onto the material, turn it with the round knob (or the arrow and turn buttons / arrow keys), then *Confirm position*. Confirm calls `POST /jobs/{id}/placement` with a rigid matrix (move and turn only); the job becomes `absolute`, the old Frame is cleared, and the pupil presses **Frame** to double-check (the picture is fisheye-curved near the edges).
- The picture and the outline share ONE svg whose units are camera pixels, so they stay registered. The camera -> bed mapping is a homography (`homography.ts`: `solveHomography`, `applyH`, `invertH`); the maths of placing and dragging is in `alignlogic.ts` (pure, tested in `tests/align.test.ts`). The page re-attaches the alignment's own element on each poll instead of rebuilding it, and `stationui.render()` does nothing while an alignment is open, so a drag is never interrupted. `camerafeed.ts` refreshes the picture (about every 0.7 s; the brief's 5 to 10 fps WebSocket feed can replace it).
- **Calibration** is done by a teacher **at the laser PC, from Station mode** (header button *Calibrate camera*, `calibrateui.ts`). Calibrating changes what every pupil sees, so the dialog asks for a *teacher token*: it is used for that dialog only (to make the marks job, run it with `skipQueue`, and `PUT` the calibration) and never stored; the station token itself cannot change a calibration. Two ways: **Cut test squares** (use this when the bed is bigger than the camera sees, which is the usual case): the laser cuts 1 or 4 squares of known size at a known bed position on a scrap (`POST /stations/{id}/calibration-marks`: a job pinned to that laser, approved, Score by default; the dialog frames it, waits for Idle, starts it, waits for Done, and cancels it if anything fails), then the teacher clicks each square's corners in the live picture; or **Bed corners** when the whole bed is in view. Many points are fitted by least squares (`solveHomographyLS`), so spread the squares over what the camera sees: the map is accurate inside the marks and only extrapolates outside them. The dialog shows the typical and worst miss in mm and an orange 50 mm grid preview; markers can be dragged. This is the approximate first version (a flat map, no lens correction); the brief's accurate version (lens calibration done by the Cutter) can replace the stored matrix without changing the API. Without a calibration (`StationInfo.calibrated` false) Station mode says so and the old flow (head to the material, Frame) still works. The Admin site's Lasers page only shows whether each camera is calibrated.
- `python -m kerf_server.devtools.fake_cutter` sends a test picture of a 400 x 400 mm bed (corners at camera pixels (110,430), (540,425), (500,40), (150,45)) so all of this can be tried without a camera.

## Stations page (Admin site): stations and Cutter software
The **Stations** page (`pages.ts`, `stations`; it was *Lasers*, and the separate *Cutter software* page is gone) lists the school's lasers with status, bed size, camera calibration and Pause/Resume/Stop. **Add a station** and **Edit** (teachers and admins) open a form (`machineform.ts`: `stationFields`, `profileFromForm`, tested) and save the machine profile with `PUT /machines/{id}`; an edit keeps every profile field the form does not show, and the ID cannot change. **Delete** (admins) calls `DELETE /machines/{id}` after a confirm; the server refuses while the Cutter is connected or files are queued for it, and the message is shown. **Cutter software** (admins) opens a dialog: choose *Practice* or *Real* (Real is disabled until the server has built it: `GET /cutter/kinds`), set the server address, press *Get the download and command* (`POST /cutter/package {station, kind}`): a new station token (shown once), a one-hour download link, the install steps and the run command (`cutterCommand` in `server.ts`; Windows for the real Cutter, Windows plus Mac/Linux for the practice one, with the Mac `Install Certificates.command` note). The server-address box defaults to the page's own address but must be the one the station's PC uses. Real Cutter: `cutter/build/kerf-cutter.zip` made by `cutter/build_cutter.py`. Practice Cutter: `server/kerf_server/devtools/package.py` (`fake_cutter.py` plus test pictures).

## A failed save is never a lost design (`localdrafts.ts`, `serverui.ts`)
If Save or Send cannot reach or satisfy the server (network down, signed out, schema problem, anything), the design is kept in this browser's local storage (`kerf.localdrafts`: the newest ten, the pupil ID and job, never a name, never sent anywhere) and the dialog says so, with the server's own list of problems (`explain`). **My files** then has an *On this computer (not on the server yet)* section: Open (loads it; a later Save to the server removes the local copy), Save to the server, Delete. It is also shown automatically after sign-in when a pupil has copies waiting. If the browser will not store it either, the dialog says to use Export DXF.

## Autosave and kept tabs (`serverui.ts`, `main.ts`, `workspace.ts` Mirror)
There is no Save button. Every change is saved twice:
- **To the server**, about 1.5 s after the last change (`noteChange` -> `autosave` -> `saveCurrent`): creates the draft the first time (not for an empty page), then PUTs it. Saves of one file are chained, and each writes to the `FileMeta` it started on, so switching tabs mid-save is safe. Leaving a tab, new tab, duplicate, sign-out and `pagehide` flush at once (`flushNow`); Ctrl/Cmd+S just says so. A failure shows "Not on the server yet: kept on this computer, trying again" and retries after 5 s, doubling to 60 s; a 401 drops the session. Status text is `#srv-save-state`. Applies to every signed-in role except stations. A tab changed in the background by *Move shapes to tab* saves when it is next shown.
- **To this browser**, within about 0.3 s (`persistTabs`): the whole workspace (every tab's full document state, so groups, text and splines survive, plus its server id and saved fingerprint, but not undo history) under `kerf.workspace.<pupil ID | "offline">` (`mirrorKey`; IDs only, never names). On a refresh, on signing in again, and when "work without signing in" is chosen, `restoreTabs` brings the tabs back (it replaces an untouched page, or adds them after work already open without duplicating a file already open). Nothing is written until the restore has been tried (`mirrorOwner`), so a refresh can never overwrite saved tabs with an empty page; an empty workspace removes the entry. Sign-out clears the screen (the next pupil sees nothing) but **keeps** the entry for that pupil, so their tabs return when they sign in again on that computer. If the server cannot be reached when the page loads, the tabs still come back. If the browser's storage is full the status says so (`setLocalOk`). Damaged entries are ignored (`parseMirror` validates every shape). Tabs on another computer come from the server instead (*My files*).
- **My files has two tabs**: *On the server* (the pupil's jobs) and *On this computer*, which lists (1) the files open in tabs now (Show), (2) **Closed tabs**: closing a tab keeps its whole file in this browser (`addClosed`, key `kerf.closed.<pupil ID>`, newest 20, one entry per server file, empty files are not kept; Open puts it back in a tab, or switches to it if that server file is already open; Delete removes only the local copy) and (3) copies kept because a *Send* failed (`localdrafts.ts`). Each list is read with the signed-in pupil's own ID as the key (`ctx.tabs.listClosed/openClosed/deleteClosed` refuse any other owner), so a pupil only ever sees and opens files made under their own ID; the server enforces the same for its list.

## Sending again replaces the old file
The Send dialog warns when the pupil already has a file waiting ("sending this replaces it, and you go to the back of the queue"), and the confirmation says which file was replaced (`Receipt.replaced`). The server does the replacing (see `server/CLAUDE.md`); the Editor only tells the pupil.

## Sign in with DINO (planner-004)
`sso.ts` (pure, tested in `tests/sso.test.ts`): `fetchAuthConfig` reads `GET /auth/config` (an older server or any failure means class code + PIN only); `beginSignIn` makes a PKCE S256 verifier and a state, keeps them in sessionStorage and sends the browser to DINO; DINO returns to **the same page** (`/` for the Editor, `/admin/` for Admin; register exactly those redirect URIs), `finishSignIn` checks `state`, trades the code at the token URL, and asks `/auth/me` who it is. The access token (a ~15 min JWT) is only in `Session.token` in memory; `Session.sso = true` makes `saveSession` skip localStorage. The rotating refresh token is in sessionStorage (`kerf.sso.refresh.<app>`) so a reload of the tab restores the sign-in (`restoreSignIn`) and closing the tab ends it. `Renewer` renews a minute before expiry and updates `session.token` in place (offline: retries in 15 s; DINO refusing: back to the sign-in page). Sign-out calls `endSignIn` (revoke, best effort). The Editor gate shows a "Sign in with DINO" button unless the server is `pins`-only, and hides the class code + PIN form when it is `planner`-only (laser stations still use a token). Admin does the same and accepts only teacher/admin. The names/emails of DINO users are never read or stored here.
