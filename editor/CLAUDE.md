# editor/ (BISAK Kerf Editor)
TypeScript PWA for Chrome/Edge desktop. paper.js for geometry, opentype.js for text. Internal units mm; Design/Bed/Screen/Camera spaces per brief section 5; Bed→Screen conversion lives in ONE function. Edits change object matrices, never source geometry. Export DXF/SVG must work standalone. Does not talk to hardware directly (no Web Serial).

## Commands (run from `editor/`)
- `npm install`, `npm run dev` (Vite dev server), `npm run build` (typecheck + bundle), `npm test` (vitest), `npm run typecheck`.
- Machine profiles are imported from `../shared/machine-profiles` at build time (`src/machine.ts`).
- `src/coords.ts` holds Bed<->Screen conversion; do not convert elsewhere. `public/sw.js` is the offline app-shell cache.

## Modules
- `geometry.ts` (segments/matrices/shapes), `select.ts` (box select), `tabs.ts` (tabs/bridges: stored on `DocObject.tabs` as fractions along the closed Cut outline plus a width in mm; `splitByTabs` turns them into the open pieces the laser cuts, applied in DXF/SVG export and, later, G-code), `repair.ts` (join loose segments into paths with a bucketed tolerance match, close, explode, and node move/insert/delete; DXF import auto-joins per layer), `fillet.ts` (also `roundedRectangle`; corner radius/chamfer of straight-line corners as true arcs; clamps to half of each edge), `icons.ts` (tool icon set + sprite), `arrays.ts` (linear repeat, circular array, mirror), `testgrid.ts` (material test grid and kerf coupon generators; cells record per-shape power/speed in `DocObject.settings`), `dialog.ts` (native <dialog> parameter form), `presets.ts` (placeholder material presets + per-laser resolution), `clipboard.ts` (strict parse of pasted Kerf clips; copy/paste uses the browser clipboard events), `align.ts` (align/distribute; groups are one unit), `boolean.ts` (union/intersect/subtract via paper.js; Bezier results are fitted back to true arcs, preferring the input circles; groups and text are compound operands), `gizmo.ts` (gimbal handle layout, hit-testing and drag maths; matrices are set from drag-start snapshots), `text.ts` (text to paths: DejaVu outline fonts via opentype.js laid out glyph by glyph, Hershey single-line fonts; live text objects are `textId` contours in `Doc`, regenerated by `retext`, flattened by `convertText`), `offset.ts` (Offset tool: parallel copies of selected shapes and lines at a distance; closed shapes go outside/inside/both, open lines left/right/both of the way they run; Clipper (`clipper-lib`, Boost licence) does the geometry on a finely flattened outline and the result is turned back into true lines and arcs by matching points to the circles an offset must lie on (concentric arcs, and arcs about the old corners for round corners); long flattened curves are simplified to within 4 micrometres; the Options panel shows a dashed live preview and can keep or replace the original), `spline.ts` (Spline tool: a smooth curve through clicked points as cubic Beziers, centripetal Catmull-Rom so it never loops or overshoots; `DocObject.spline` remembers the through-points so the Nodes tool drags/inserts/deletes points and the curve is re-fitted; any other edit calls `convertText` which drops the spec, leaving a plain cubic path; splines go to the job as ordinary `cubic` segments, and are not restored as splines when a saved file is reopened), `dimensions.ts` (dimension annotations: linear aligned/horizontal/vertical and radial diameter/radius; pure geometry for drawing, picking and labels; they live in `Doc.state.dimensions`, are drawn teal, selectable (Delete removes), toggled with the Dimensions checkbox, and are **annotations only: never in DXF/SVG export, never in the job's objects or G-code**; they are saved with the job in the schema's `dimensions` array and come back when a file is reopened), `snap.ts` (snap planner; object snaps beat the grid), `ruler.ts` (ruler ticks, measure), `bounds.ts` (out-of-bed check, canSubmit), `status.ts` (footer text), `trim.ts` (trim: pure planner, bakes placement into the kept paths), `anchor.ts` (3x3 anchor, numeric X/Y position and W/H resize, scale % and rotate, all about the anchor), `doc.ts` (objects + undo/redo), `export.ts` (DXF/SVG), `dxf-import.ts` (LINE, ARC, CIRCLE, LWPOLYLINE, POLYLINE, SPLINE), `main.ts` (UI).
- Import converts, normalises and auto-joins touching entities per layer (units -> mm; a file with no `$INSUNITS` is assumed to be centimetres, the Onshape default; bbox bottom-left -> 0,0). Dedupe/overlap-merge clean-up is Server work (join is done here too, so the editor works standalone). Unsupported entities (TEXT, HATCH, ELLIPSE...) are counted and reported, not imported.
- Groups are a `group` id on `DocObject` (one level; grouping again merges). Selection and moves always go through `Doc.expand()` so group members act together. The 1 cm grid is drawn by `drawGrid` in `main.ts` (toggle in the toolbar).

## Server (pupil sign-in, files)
Pupils sign in with **class code + pupil ID + PIN** (`loginWithPin`; the server returns a short-lived token, sign-out revokes it; the class code is remembered, the PIN never is). Teachers and laser stations use the "sign in with a token" link. On the Admin site, a class's **Pupils and PINs** (`classesui.ts`) creates classes, adds pupil IDs (paste a list) and shows each new PIN once with copy/download, resets PINs and removes pupils. Sign-in is on a full-screen gate (`#gate` in `index.html`); a small "work without signing in" link keeps the Editor usable offline (Save / Send then ask to sign in). `server.ts` is the API client (token + address in localStorage; errors become readable `ServerError`s), `job.ts` converts the page to a job document and back (`buildJob` / `fromJobObjects`; tab fractions <-> `atLengthMm`; arc `ccw` <-> `clockwise`; groups and live text are not stored, text reopens as plain paths), `serverui.ts` has the top-bar buttons and the gate: **Save** (creates a draft, then updates it with PUT), **Send for cutting** (save, then submit; asks where to place it: at the laser head with an anchor, or exactly on the bed), **My files** (Open a draft to keep working, Open a copy of anything already sent, Send, Cancel; shown automatically after sign-in if the pupil has files). A fingerprint of the page detects unsaved changes (confirm before opening another file or signing out; `beforeunload`). Sign-out empties the page and the undo history (`Doc.reset`) so the next pupil never sees it. On sign-in the material list becomes the server's presets (`presetStore` in `presets.ts`). Served by the server the address is blank (same origin); under `npm run dev` enter the server address and set `KERF_CORS_ORIGINS=http://localhost:5173` on the server. 
**Station mode and the teacher screen** (`stationui.ts`, pure helpers in `stationlogic.ts`): signing in with a *station* token (`kerf-admin create-token --role station --id station-1`) opens a full-screen Station view instead of the design Editor: the queue (with "Next" highlighted for this laser), the next job's outline preview, material and size, then **Frame** (laser off, trace the outline) -> tick "I have loaded <material>" -> **Start cutting**; while cutting it shows progress, elapsed/estimated time, Pause/Resume/Stop and the camera picture if there is one; "Not ready: let the next person go" defers the ticket. It polls every 2 s and only offers what the server will accept (`stepState`); the server still enforces everything. A *teacher* or *admin* token has no Queue or Classes buttons in the Editor any more: the Editor shows an **Admin site** link instead (see below). Try it all without a laser using `python -m kerf_server.devtools.fake_cutter`.

## Activities and feedback
A class's teacher sets **activities** (title, instructions, optional suggested material and due date, visible/hidden, ordered). Pupils see them under **Activities** in the top bar: *Start working* sets the current activity (shown in the top bar with a x to stop; files saved while it is current carry its `activityId`) and opens the file already made for it, *Hand in for review* saves the page then submits the latest file; status chips: Not started / Working / Handed in / Please improve / Complete; feedback from the teacher is shown there. Teachers (Admin site): **Classes** -> *Activities…* / *Progress…* (or the Activities page): manage activities (new, edit, publish/hide, reorder, duplicate, archive, and *Copy from another class…*: tick which activities, optionally keep due dates / publish at once; copies start hidden with no due date; pupils' work and feedback are never copied) and a pupils x activities **Progress** grid; click a cell to see the pupil's file (outline preview, *Open in the Editor* as a copy) and give feedback: comment, ask to improve (pupil sees "Please improve" and can resubmit) or mark complete. Code: `activitiesui.ts` (+ `dom.ts` helpers, API in `server.ts`).

## Fonts
`public/fonts/` holds DejaVu (free licence, see DEJAVU-LICENSE.txt). `src/fonts/hershey.json` is a subset of the Hershey single-line fonts via the MIT-licensed hersheytext package (HERSHEYTEXT-LICENSE.txt). opentype.js 2.x has no types (`src/opentype.d.ts`) and throws on some GSUB tables, so never call `font.getPath(text)`; lay out per glyph.

## Layout (LightBurn-style)
`index.html` + `src/style.css`: top bar (file, history, edit, view, Tools menu, laser), left two-column tool palette holding EVERY tool and action as an icon button (draw, edit, boolean, arrange, align, repeat; icons live in `src/icons.ts` and are injected as an SVG sprite, `tests/icons.test.ts` checks every icon is used, every button has a tooltip and aria-label), canvas centre, right sidebar (Properties, Options, Cuts / Layers), bottom bar (Cut/Score layer chips + material picker with locked settings), footer (selection size, notices, cursor). Element ids are the contract with `main.ts`: keep them when moving things around.
- The layer chips set the layer for NEW shapes (`activeLayer`) and move the current selection onto that layer.
- `presets.ts` holds PLACEHOLDER presets in the shape of `shared/preset.schema.json` (a test validates them against it); `resolvePreset` applies per-laser overrides and flags untested lasers. The chosen preset id lives in `Doc.state.materialId`. Pupils see the settings locked.

- Palette actions disable themselves when they cannot apply (`refreshActions` in `main.ts`): booleans/group need 2+ shapes, space needs 3+, etc.

## Admin site (`admin/index.html`, `src/admin/`)
A second Vite page at **/admin/** (built into `dist/admin/`, served by the Server next to the Editor). For teachers, school admins and the platform owner; pupils and laser stations are turned away. Sign in with a token (kept under its own localStorage key, `kerf.admin.session`). `main.ts` is the shell (sign-in, nav, school name), `pages.ts` the pages, `admin.css` the layout (it also loads the Editor's `style.css` for dialogs, chips and tables).
- Teacher / admin pages: **Overview** (waiting files, queue, lasers online, classes, pupils; refreshes), **Classes** (new class, per-class approval: "A teacher approves each file" / "Straight to the queue", Pupils and PINs, Activities, Progress), **Pupils** (all pupils by class: new PIN, remove), **Activities** (every class's activities with progress counts; Manage opens the existing class-work dialog), **Queue** (`mountQueue` in `stationui.ts`: approve/reject, reorder, cancel; refreshes), **Lasers** (status, pause/resume/stop). Admin adds **Staff** (teachers, admins and station tokens, shown once; revoke). The platform owner sees only **Schools** (create a school and its first admin; the token is shown once).
- Everything is the school of the signed-in token: the server filters, the site never asks for a school. The Editor shows an **Admin site** link to teachers and admins (and sends a platform token straight there); *My files* is for pupils only.
- Pupil files are looked at as a preview here (no "Open in the Editor" any more).
