# server/ (Kerf Server)
Python: FastAPI, SQLAlchemy (SQLite default, PostgreSQL via `KERF_DATABASE_URL`), ezdxf, shapely, jsonschema. Schemas and the API contract come from `shared/` (the server validates against them; `shared/tests` checks version agreement). Type hints, pytest. `README.md` documents the workflow and deployment.

## Layout
- `app.py` app factory (`/api/v1`, `/health`, optional website + Editor: `webpages.py` routes, then the static mount). `config.py` KERF_* settings. `security.py` hashed bearer tokens, roles pupil/teacher/station. `admin.py` the `kerf-admin` CLI.
- `cleanup/` DXF clean-up in brief section 7 order (dedupe/merge before join). Entry `cleanup_dxf`.
- `gcode/` post-processor: `prepare` (matrices to bed space, arcs kept unless the matrix distorts them), `kerf` (kerf offset via shapely then arcs re-fitted; GRBL centre snapping), `order` (Score first, Cut inside-out), `emit` (G21/G90, no G92, G2/G3, tabs as S0 moves, passes, air), `estimate` (GRBL-style planner), `motion` (G-code parser used as a simulator in tests and as a safety check on our own output).
- `services_jobs.py` job lifecycle + validation; `services_run.py` frame/assign/finish/watchdog; `stations.py` live Cutter state, logs; `api/*` routers; `api/cutter_ws.py` the `/api/v1/ws/cutter` socket.

## Rules that bite
- Machine facts (bed, `$30`, air assist) come from machine profiles; the Cutter's reported `$30`/`$32` must match or the job is refused.
- Absolute G-code only, never G92. `current-position` jobs are translated by the server using the Cutter's reported position; the head must not move between Frame and Start.
- Never hold a DB session open while awaiting the Cutter (SQLite would lock); `services_run.start` does the work in two short transactions.
- Pupil IDs only, never names (uploaded file names are discarded). Camera frames stay in memory.
- Preset edits create new versions; jobs record the version used.
- Layer `ignore`: the pupil's own shapes. `gcode.cuttable(job)` drops them before G-code, estimate, extent, wastage, kerf, the fit check and `probe_head`; a job with only ignored shapes raises `GcodeError("nothing to cut")`. They are stored and returned with the job.
- File names, delete and the open tabs (shared 0.2.25): `Job.name` (the pupil's title, `clean_name`: trimmed, 60 chars), `PUT /jobs/{id}/name` (owner only, any state), `DELETE /jobs/{id}` (owner only; drafts, cancelled/rejected and failed files; `in_queue` while waiting or on a laser, `keep_record` for a finished cut, `handed_in` for work handed in for an activity; the G-code and events go too, in-progress activity work just loses its link). `services_workspace.py` / `api/workspace.py`: `GET`/`PUT /workspace` keep one row per person (`Workspace`: tab order, tab names, the active tab; at most 30) and only ever return the caller's own, still existing files, so a deleted or foreign id drops out. The content of a tab is its job (autosave), never stored here.
- Open Cut paths (`check_cut_paths`): with `KERF_OPEN_CUT_PATHS=block` (default) a send is refused with `open_cut_path` **unless** `POST /jobs/{id}/submit` carries `{acceptOpenPaths: true}` (the Editor sends it after warning the pupil); then it goes through with the warning "N open path(s) on the Cut layer will be cut as drawn". `warn` mode never refuses. Nothing else (bed, preset, G-code) is excused by the flag.
- **Arc fitting must never invent a curve** (`gcode/kerf.py` `fit_arcs`/`_fits`). After a kerf offset the outline is re-fitted to G2/G3 arcs. A kerf offset leaves a tiny bevel (2 to 6 micrometres, growing with the kerf) of near-duplicate vertices at every sharp corner, so a run of five points can really be three corners, and three points always lie on a circle: a pupil's polygon star was cut as a circle (arcs through two tips and the valley between them, up to 4 mm off the drawing; it needed a mirrored or stretched shape plus kerf to show). The fitter now collapses vertices closer than 2 micrometres (`_distinct`), refuses a run with any neighbouring points closer than `MIN_CHORD_MM` (0.02 mm; a real arc's are 0.05 mm or more) or further apart than `MAX_STEP_RAD` (30 degrees) seen from the fitted centre. Regression tests in `tests/test_gcode.py` replay the failing stars and sweep points x flip x kerf x angle; keep them when touching the fitter. A 4,800-star random sweep (rotation, stretch, mirror, kerf 0 to 0.5) now finds no arcs and nothing further than the kerf from the drawn outline.
- Job `dimensions` (Editor annotations) are stored and returned with the job but never read by `gcode/`, validation, estimates or the Cutter messages.
- Ticket queue (`services_queue.py`): approved jobs get an ever-increasing ticket and are served first in, first out by `rank` (moved only by a teacher or `defer`). A station may only frame/start the job that is next for it (`not_your_turn`); jobs pinned to another station and jobs framed (reserved) on another station are skipped; teachers may `skipQueue`. A refused start keeps its place.
- Class login (`services_classes.py`): pupil ID + class code + PIN -> expiring token. PINs are scrypt-hashed, never logged or returned again; wrong class/ID/PIN give one identical 401; per-pupil lockout and per-IP throttle; IDs only, never names. `Token.expires_at` is checked in `security.lookup`.
- Activities (`services_activities.py`): `SchoolClass.teacher_id` owns a class (None = shared); `owned_class` makes other teachers' classes 404. Pupils only see published, unarchived activities of their own class (`Pupil.class_code`). `Job.activity_id` links a file; `ActivityWork` holds status; `Feedback` rows are signed with a teacher ID. `Database._add_missing_columns` adds new model columns to older databases.
- Schools (`services_schools.py`, `api/schools.py`): every class, job, laser (`MachineRow`), token and preset list carries a `school_id`; `Principal.school` is set from the token (pupils from their class). Roles: pupil, teacher, admin (a teacher for every class in their school + staff management), station, platform (creates schools, sees inside none). **Every query must filter by `who.school`** (or `j.school_id`): another school's data answers 404. Queue tickets/rank are per school. Class codes, pupil IDs and laser IDs are unique server-wide on purpose; a station token may only connect as a laser registered to its own school (`cutter_ws`). Presets are keyed (school, id, version). Old databases move into the `main` school at start-up (`Database.create_all`, `services_seed`). `tests/test_schools.py` is the isolation suite: add to it whenever you add an endpoint.
- Approval is a per-class setting (`SchoolClass.require_approval`, default yes; `services_classes.needs_approval`); `KERF_REQUIRE_APPROVAL=false` still turns it off for everyone.
- Camera alignment: `MachineRow.camera_calibration` (camera pixels -> bed mm homography, four clicked corners; `services_presets.check_calibration` re-projects the points and refuses a wrong matrix) via `/stations/{id}/camera-calibration` (teacher writes; station or teacher reads; per school). `services_run.place` / `POST /jobs/{id}/placement` applies a *rigid* matrix (move and turn only) to every object, makes the job absolute, rejects anything that no longer fits the bed (nothing changes), clears the old frame, and only the job whose turn it is can be placed. `GET /stations` carries `calibrated`.
- Calibration marks (`services_jobs.calibration_marks`, `POST /stations/{id}/calibration-marks`, teacher only): a job of 1 or 4 known squares, `source="calibration"`, owned by the teacher's ID, pinned to the laser and approved. It sits in the queue until cut or cancelled, so the Station mode dialog cancels it if the run fails. A calibration may have 4 to 64 points (4 fitted exactly, more by least squares; the server only re-projects them as a sanity check).
- Cutter download (`api/cutter.py`, `devtools/package.py`): `POST /cutter/package {station, kind: practice|creality-falcon}` (admin, own school's lasers; `creality-falcon` is 409 `cutter_not_built` until `cutter/build/kerf-cutter.zip` or `KERF_CUTTER_ZIP` exists) issues a station token via `services_schools.add_staff` and an in-memory one-hour link in `app.state.download_links`; `GET /downloads/cutter/{link}/{name}` needs no Authorization header (a browser link cannot send one) and the zip holds no token. `GET /cutter/kinds` says which kinds are on offer (`package.available`); the download is chosen by the file name in the link (`package.read`). `DELETE /machines/{id}` (admin) removes a laser, its calibration and its station tokens, refused while its Cutter is online (`station_online`) or files are queued/assigned/running for it (`station_in_use`). `fake_cutter.py` must stay standalone (stdlib + `websockets`, pictures read next to the file) because the zip ships it alone.
- Older Editors still save: `schemas.validate` treats a document's `schemaVersion` as the current one when only the last number differs (every 0.N.x change to `shared/` is additive), so a cached tab or an un-updated PC is not locked out by a server update. A different 0.N or a major version, and every other schema error, is still refused with its paths.
- A new send replaces the old one (`services_jobs.replace_waiting`, called from `submit` after validation; `KERF_REPLACE_OLD_SENDS`, default on): the same pupil's earlier files that are `submitted` or `approved` are cancelled ("Replaced by a newer file (job-...)", event `replaced`), the new file takes a new ticket at the back, an activity hand-in that pointed at the old file follows the new one. `assigned`/`running` files, drafts and calibration marks are never touched, and a send that fails validation cancels nothing. The receipt lists `replaced`. The shared test settings turn it off (many tests put several files from one pupil in the queue); `TestANewSendReplacesTheOldOne` turns it on.
- Sign in with planner-004 (`sso.py`, design in `docs/AUTH-PLANNER-004.md`): `KERF_AUTH_MODE` = `planner` (default) | `both` | `pins` (tests/dev only), `KERF_SSO_ISSUER` (planner-004's origin, required unless `pins`), `KERF_SSO_AUDIENCE` (`kerf-sabre`), `KERF_SSO_JWKS_URL`, `KERF_SSO_CLIENT_EDITOR/ADMIN`, `KERF_SSO_SCOPES` (default `profile groups`: what sign-in asks DINO for; DINO refuses the whole sign-in if a client lacks one, so set `profile` while a client lacks `groups`). `security.current_principal` sends a bearer starting `eyJ` to `Verifier.principal`: RS256 only, header `typ: at+jwt`, `iss`/`aud`/`exp`/`nbf`/`sub` required, `client_id` must be ours, keys cached 5 min and refetched at most every 30 s on an unknown `kid` (stale keys keep working if DINO is down; no keys at all is 503 `sso_unavailable`). Roles: admin > teacher > technician > pupil, else 403; a JWT can never be station or platform. `sub` is the person's ID; no name or email is stored or logged. A DINO pupil is not auto-added to a class: a teacher adds their DINO ID as a pupil (the PIN is then unused). `GET /auth/config` tells the Editor how to sign in; `planner` mode answers `POST /auth/login` with 404 `sso_only`. Tests use a local key and a fake JWKS (`tests/test_sso.py`).
- **DINO is the only way in, and `technician` runs the stations** (shared 0.2.19, 0.2.20). `KERF_AUTH_MODE` defaults to `planner` (needs `KERF_SSO_ISSUER`; the server will not start without it). `security.lookup(..., people_tokens=False)` refuses any stored pupil/teacher/admin/technician token (401): only `station` (the Cutter) and `platform` tokens are stored tokens. `/auth/login` answers 404 `sso_only`; `POST /staff` and `kerf-admin create-token/import-pupils/reset-pin` and `POST /schools` with `adminId` are refused for people. `pins`/`both` exist for tests and local demos (`tests/conftest.py` sets `KERF_AUTH_MODE=pins`; `server/run-local.sh` and `start.py` do too). Role `technician` (from DINO `roles`, below teacher: admin > teacher > technician > pupil) is accepted wherever `require("station")` is (`security.require` adds it), may calibrate cameras and `skipQueue` (`Principal.can_override_queue`), and is refused everywhere that needs a teacher/admin. Tests: `tests/test_sso.py` (`TestOnlyDinoSignsPeopleIn`, `TestTechnician`).
- A technician may reject a queued (approved) file with a note (`POST /jobs/{id}/reject`, `require("teacher","technician")`; 409 for a file not yet approved); the stored reason is `Rejected at the laser: <note>` so the pupil can tell who stopped it. Picking a file ahead of the queue uses the existing `skipQueue` flag on frame/placement/assign (`Principal.can_override_queue`). `TestTechnicianPicksAndRejects` in `tests/test_sso.py`.
- **Display names** (shared 0.2.22; `models.Person`, `services_people.py`, `POST /auth/profile`): the Editor/Admin call it after a DINO sign-in; the server asks DINO's `/oauth/userinfo` with the caller's own bearer (`Verifier.userinfo_name`; tests replace `fetch_userinfo`), keeps only a cleaned `name` (no control characters, no `@`, 128 chars; never an email), and never logs it. Staff get `pupilName` on queue entries and job lists and `displayName` on class pupils and the progress grid, **only for their own school**; pupils never see anyone's name. `services_classes.remove_pupil` calls `people.forget`. `TestDisplayNames` in `tests/test_sso.py`.
- **Disconnecting a Cutter** (shared 0.2.23): `POST /stations/{id}/disconnect` (teacher/admin/technician) closes the Cutter's socket with 4001 and marks it offline at once; refused while it is cutting. Close codes the Cutter must not reconnect after (`cutter/kerf_cutter/net/client.py` `STAY_AWAY_CODES`): 4000 replaced by another Cutter, 4001 disconnected by staff, 4401 token refused, 4403 a Cutter that names another laser than its token's (`api/cutter_ws.py`). The practice Cutter (`fake_cutter.py`) exits with a plain message for each.
- **Taking over a file** (shared 0.2.25): `POST /jobs/{id}/take {station}` (teacher/admin/technician; `services_run.take_over`) re-pins a waiting file that a teacher gave to another laser (or that was framed on one) to this laser: same queue place, the other laser's frame is cleared, event `taken_over`. Without it frame/assign still answer `wrong_station`.
- **What the Server decided is logged** (`services_run.note`): every frame and start request, its head position, origin and result or refusal (with the reason), and the `run_job` it sends, go into the station's log (`GET /stations/{id}/logs`, next to the Cutter's own lines) and the Server's console (logger `kerf.run`). A "does not fit" error states the outline's span, the head position and the bed. A head-placed design that pokes past the bed by up to 2 mm only because of the kerf (a star's tips at the origin corner) is moved back onto it with a warning (`gcode.generate`, `NUDGE_MAX_MM`).
- **Auto-approve switch** (shared 0.2.26): `School.auto_approve` (NULL = `Settings.auto_approve_default`, env `KERF_AUTO_APPROVE`, default on), `GET/PATCH /school`. `services_jobs.submit` approves a new file at once while it is on, before the per-class and server-wide approval rules; files already waiting are untouched. The shared test settings turn the default off (`tests/conftest.py`, `test_sso.py` fixtures) so the approval tests keep their waiting files; `TestAutoApprove` covers it.
- **Test-gridded materials** (shared 0.2.27): `POST /presets/{id}/tested {station, tested}` (teacher/admin/technician) edits `testedOn` as a new preset version. **An untested material never blocks a cut** (the owner's decision: test grids are ad hoc): it is only a warning on the file and a note on the Station page; `allowUntested` is still accepted and ignored.
- **Deleting materials, changing a file's material, processed files** (shared 0.2.29): `PresetRow.deleted` marks every version of a deleted material (`services_presets.delete_preset`, `DELETE /presets/{id}`, refused with `material_in_use` while submitted/approved/assigned/running files use it); `latest_preset`/`list_latest_presets` skip it, `preset_version` does not (old files stay reproducible), `submit` refuses a draft in a deleted material, and creating the same id again continues its version numbers. `PUT /jobs/{id}/preset` (`services_jobs.change_preset`, teacher/admin/technician; submitted or approved only) keeps the queue place, re-runs `validate_for_cutting` (reverting on failure) and clears the frame. `POST /jobs/{id}/requeue` (`services_jobs.requeue`, teacher/admin) puts a done/failed/cancelled file back as approved with a new ticket at the back. `GET /jobs` takes `limit`. Tests: `TestMaterialsAndProcessedFiles` in `tests/test_queue.py`, plus `test_schools.py`.
- **MCP for staff** (`mcp_layer/`, `KERF_MCP=1`, `KERF_PUBLIC_URL`, design and the planner-004 side in `docs/MCP-KERF.md`): a stateless read-only MCP server at `POST /mcp` (JSON-RPC, protocol in `protocol.py`, six tools in `tools.py`: `list_files`, `get_file`, `get_gcode`, `get_queue`, `list_stations`, `get_station`; routes + OAuth protected-resource metadata in `routes.py`). Off by default (404). Teacher/admin/technician only (pupil, station, platform: 403). Tools call the same services as the REST API with the caller's `Principal`, so **every query still filters by `who.school`**; `tests/test_mcp.py::TestSchoolsAreWalls` is the isolation suite (add to it with every tool). **No tool may change anything** (all carry `readOnlyHint`); a write tool is a separate decision. A DINO JWT must carry `aud` = the MCP resource (`Verifier.verify(..., audience=cfg.mcp_aud, any_client=True)`): Editor tokens (`kerf-sabre`) are refused on `/mcp` and MCP tokens on the REST API; stored tokens work only outside `planner` mode. Audit line per call (logger `kerf.mcp`): DINO `sub`, role, tool, ok; never arguments, names, results or tokens. Output is capped (`MAX_RESULT_BYTES`, design 100 KB, G-code 2000 lines, logs 100). Why not the `mcp` SDK: see the doc. Needs no new dependency.

- **Groups** (shared 0.2.30; `api/groups.py`, `Verifier.groups`): `GET /groups` (teacher/admin) = `[{id,name,subject,yearGroup,pupils:[IDs]}]`. With DINO sign-in it asks DINO `GET {issuer}/oauth/groups` with the teacher's own bearer (needs the `groups` scope at sign-in; an older token without it, or DINO down, is `502 groups_unavailable`), drops ids Kerf cannot hold and `teaching:false` groups, keeps IDs only. Without DINO (pins/both) it is Kerf's own classes. Tests: `TestDinoGroups` (`test_sso.py`), `TestGroupsWithoutDino`.
- **Free and paid schools, school codes, site admins** (shared 0.2.32; design `docs/ACCOUNTS.md`): `School.plan` (`free`/`paid`; NULL = a school from before plans = paid) and `School.code` (5 characters, `CODE_ALPHABET` has no look-alikes, unique across Kerf; `ensure_codes` gives old schools one at start-up). The paid service is gated by `deps.PAID` (`dependencies=PAID` on the routes: the queue and approval, submit, Station pages and lasers, the Cutter download, the camera, activities) and `services_schools.require_paid` (`POST /jobs` with `submitted`), answering `403 paid_feature`; the Cutter WebSocket closes with 4402 for a free school. New schools default to `free`. Site admins (`Principal.site_admin`): DINO accounts in `KERF_SITE_ADMINS`, or a stored platform token; `security.require_site_admin` guards `GET/POST /schools` and `PATCH /schools/{id} {plan, name}`. `/auth/me` adds `siteAdmin`, `plan`, `schoolName`, `schoolCode`. Tests: `tests/test_plans.py`; the `test_schools.py` world makes its schools paid.
- **Per-school sign-in** (shared 0.2.33; `services_signin.py`): `School.sign_in` JSON (NULL = a school from before = DINO only; new schools: group code + email on), `GET/PATCH /school/sign-in` (admin changes; Google/Microsoft need `KERF_GOOGLE_CLIENT_ID`/`KERF_MICROSOFT_CLIENT_ID`; DINO only for `KERF_SSO_SCHOOL`; never all staff methods off). DINO sign-ins belong to `KERF_SSO_SCHOOL` (default `main`) and are refused with `403 sign_in_off` when that school turns DINO off (site admins excepted). `Identity` (provider, subject -> person_id, school) links sign-ins to people; `POST /auth/profile` records the DINO one. Only DINO has a sign-in screen today (`AVAILABLE`); group code and email come next. Tests: `TestPerSchoolSignIn` in `tests/test_sso.py`.
- **Groups hold pupils in several groups; join codes; archiving; free limits** (shared 0.2.34): `GroupMember` (class_code, pupil_id) is membership; `Pupil.class_code` stays as the home group (first group, fixes the school) and moves to another group when the pupil leaves it. `services_classes.groups_of/in_group/member_ids/member_counts` are the only way to ask who is in a group (never `Pupil.class_code`); `ensure_members` backfills old databases at start-up. Login works through any non-archived group; activities show for all of a pupil's groups; approval is needed if any group asks. `SchoolClass.join_code` (NULL = code, unique per school via `_check_join_code`), `archived`, `source`/`source_id`. Free limits: `services_schools.check_limit` (409 `limit_reached`, details `[{limit,max,current}]`) in `create_class`/unarchive (groups), `add_pupils` (checked before anything is added) and `services_jobs.create` (files per pupil, not calibration). Tests: `tests/test_groups_multi.py`.
- **Terms** (shared 0.2.35; `services_terms.py`, design `docs/ACCOUNTS.md` "Terms"): a free school's plan is `School.terms` JSON (features `laser`/`activities`, limits incl. `laserGroups`, time-limited `grants`); a paid school (`plan` paid or NULL) has `EVERYTHING`. Gates: `deps.PAID` = feature `laser`, `deps.ACTIVITIES` = feature `activities` (both 403 `paid_feature`); `services_schools.is_paid/require_paid/check_limit` delegate to it; `services_jobs.submit` checks `laser` and, while `laserGroups` is limited, that a pupil is in a `SchoolClass.laser` group (403 `not_laser_group`). `services_classes.set_laser` (admin only, `PUT /classes/{code} {laser}`). Tests: `tests/test_email_signin.py`.

## Website and the Editor's address (`webpages.py`, tests in `tests/test_webpages.py`)
With `Settings.editor_dist` (`KERF_EDITOR_DIST`, the built `editor/dist`), `add_site_routes` runs before the static mount: `/` is the landing page (`site/index.html`), `/pricing` and `/sign-in` the other site pages, **`/editor/` the Editor** (`index.html`; `/editor` redirects with its query) and `/admin/` the Admin site. A request to `/` with `station`, `code`/`state`/`error`, `signin` or `offline` is a 302 to `/editor/` with the same query (`editor_forward`; the same table is `editor/src/site/routes.ts`), so DINO keeps its registered redirect URIs (`<origin>/`, `<origin>/admin/`) and old links work. `/editor/` and `/admin/` are served with `<meta name="kerf-sign-in" content="/sign-in">`, which tells them to send signed-out people to `/sign-in` (they keep their own sign-in screens without it). HTML is `Cache-Control: no-cache`. A build without `site/` still shows the Editor at `/`. Everything else (`/assets/`, `/sw.js`, `/fonts/`) is the static mount; `/api/v1`, `/health` and `/mcp` are untouched. **Emailed sign-in and invite links** (`services_staffmail._url`) are `<base>/sign-in?signin=<token>&app=admin|editor`; the sign-in page trades the token and opens the app (older `/admin/?signin=` and `/?signin=` links still work).
- **Pupil Card sign-in** (shared 0.2.39; `services_passwords.py`, `services_classes.group_login`): `POST /auth/pupil {schoolCode, groupCode, pupilId, password}` finds the school by its code and the group by its **join code** (not archived), checks the pupil is in it and not archived, and checks the school's `groupCode` sign-in method (`403 sign_in_off`). Wrong anything is one `401 bad_login` (the same scrypt work for an unknown pupil); per-pupil lockout and per-IP throttle via `_password_login`, shared with the old `/auth/login`. The session token has `method="group"`, accepted by `security.lookup` in `planner` mode (like `email`). New pupils get a **two-word password** (`new_password`: two different words from `WORDS`, 397 child-friendly words); `normalise` makes case, spaces, dots and underscores between words irrelevant, and hashes are of the normalised form (old digit PINs still check). `add_pupils(..., entries=[{id?, name?}], generate=N)` makes 5-digit IDs (`new_pupil_id`, server-wide unique) and stores names via `people.remember`; `created[]` carries `password` (and `pin`, the same). `POST /classes/{code}/passwords` (`new_group_passwords`) and `PUT /classes/{code}/pupils/{id} {displayName}` (`set_display_name`). `services_signin.AVAILABLE` includes `groupCode`. Tests: `tests/test_pupil_cards.py`.
