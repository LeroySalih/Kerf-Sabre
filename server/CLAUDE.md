# server/ (BISAK Kerf Server)
Python: FastAPI, SQLAlchemy (SQLite default, PostgreSQL via `KERF_DATABASE_URL`), ezdxf, shapely, jsonschema. Schemas and the API contract come from `shared/` (the server validates against them; `shared/tests` checks version agreement). Type hints, pytest. `README.md` documents the workflow and deployment.

## Layout
- `app.py` app factory (`/api/v1`, `/health`, optional Editor static mount). `config.py` KERF_* settings. `security.py` hashed bearer tokens, roles pupil/teacher/station. `admin.py` the `kerf-admin` CLI.
- `cleanup/` DXF clean-up in brief section 7 order (dedupe/merge before join). Entry `cleanup_dxf`.
- `gcode/` post-processor: `prepare` (matrices to bed space, arcs kept unless the matrix distorts them), `kerf` (kerf offset via shapely then arcs re-fitted; GRBL centre snapping), `order` (Score first, Cut inside-out), `emit` (G21/G90, no G92, G2/G3, tabs as S0 moves, passes, air), `estimate` (GRBL-style planner), `motion` (G-code parser used as a simulator in tests and as a safety check on our own output).
- `services_jobs.py` job lifecycle + validation; `services_run.py` frame/assign/finish/watchdog; `stations.py` live Cutter state, logs; `api/*` routers; `api/cutter_ws.py` the `/api/v1/ws/cutter` socket.

## Rules that bite
- Machine facts (bed, `$30`, air assist) come from machine profiles; the Cutter's reported `$30`/`$32` must match or the job is refused.
- Absolute G-code only, never G92. `current-position` jobs are translated by the server using the Cutter's reported position; the head must not move between Frame and Start.
- Never hold a DB session open while awaiting the Cutter (SQLite would lock); `services_run.start` does the work in two short transactions.
- Pupil IDs only, never names (uploaded file names are discarded). Camera frames stay in memory.
- Preset edits create new versions; jobs record the version used.
- Layer `ignore`: the pupil's own shapes. `gcode.cuttable(job)` drops them before G-code, estimate, extent, wastage, kerf, the fit check and `probe_head`; a job with only ignored shapes raises `GcodeError("nothing to cut")`. They are stored and returned with the job.
- Job `dimensions` (Editor annotations) are stored and returned with the job but never read by `gcode/`, validation, estimates or the Cutter messages.
- Ticket queue (`services_queue.py`): approved jobs get an ever-increasing ticket and are served first in, first out by `rank` (moved only by a teacher or `defer`). A station may only frame/start the job that is next for it (`not_your_turn`); jobs pinned to another station and jobs framed (reserved) on another station are skipped; teachers may `skipQueue`. A refused start keeps its place.
- Class login (`services_classes.py`): pupil ID + class code + PIN -> expiring token. PINs are scrypt-hashed, never logged or returned again; wrong class/ID/PIN give one identical 401; per-pupil lockout and per-IP throttle; IDs only, never names. `Token.expires_at` is checked in `security.lookup`.
- Activities (`services_activities.py`): `SchoolClass.teacher_id` owns a class (None = shared); `owned_class` makes other teachers' classes 404. Pupils only see published, unarchived activities of their own class (`Pupil.class_code`). `Job.activity_id` links a file; `ActivityWork` holds status; `Feedback` rows are signed with a teacher ID. `Database._add_missing_columns` adds new model columns to older databases.
- Schools (`services_schools.py`, `api/schools.py`): every class, job, laser (`MachineRow`), token and preset list carries a `school_id`; `Principal.school` is set from the token (pupils from their class). Roles: pupil, teacher, admin (a teacher for every class in their school + staff management), station, platform (creates schools, sees inside none). **Every query must filter by `who.school`** (or `j.school_id`): another school's data answers 404. Queue tickets/rank are per school. Class codes, pupil IDs and laser IDs are unique server-wide on purpose; a station token may only connect as a laser registered to its own school (`cutter_ws`). Presets are keyed (school, id, version). Old databases move into the `main` school at start-up (`Database.create_all`, `services_seed`). `tests/test_schools.py` is the isolation suite: add to it whenever you add an endpoint.
- Approval is a per-class setting (`SchoolClass.require_approval`, default yes; `services_classes.needs_approval`); `KERF_REQUIRE_APPROVAL=false` still turns it off for everyone.
- Camera alignment: `MachineRow.camera_calibration` (camera pixels -> bed mm homography, four clicked corners; `services_presets.check_calibration` re-projects the points and refuses a wrong matrix) via `/stations/{id}/camera-calibration` (teacher writes; station or teacher reads; per school). `services_run.place` / `POST /jobs/{id}/placement` applies a *rigid* matrix (move and turn only) to every object, makes the job absolute, rejects anything that no longer fits the bed (nothing changes), clears the old frame, and only the job whose turn it is can be placed. `GET /stations` carries `calibrated`.
- Calibration marks (`services_jobs.calibration_marks`, `POST /stations/{id}/calibration-marks`, teacher only): a job of 1 or 4 known squares, `source="calibration"`, owned by the teacher's ID, pinned to the laser and approved. It sits in the queue until cut or cancelled, so the Station mode dialog cancels it if the run fails. A calibration may have 4 to 64 points (4 fitted exactly, more by least squares; the server only re-projects them as a sanity check).
- Cutter download (`api/cutter.py`, `devtools/package.py`): `POST /cutter/package {station, kind: practice|creality-falcon}` (admin, own school's lasers; `creality-falcon` is 409 `cutter_not_built` until `cutter/build/kerf-cutter.zip` or `KERF_CUTTER_ZIP` exists) issues a station token via `services_schools.add_staff` and an in-memory one-hour link in `app.state.download_links`; `GET /downloads/cutter/{link}/{name}` needs no Authorization header (a browser link cannot send one) and the zip holds no token. `GET /cutter/kinds` says which kinds are on offer (`package.available`); the download is chosen by the file name in the link (`package.read`). `DELETE /machines/{id}` (admin) removes a laser, its calibration and its station tokens, refused while its Cutter is online (`station_online`) or files are queued/assigned/running for it (`station_in_use`). `fake_cutter.py` must stay standalone (stdlib + `websockets`, pictures read next to the file) because the zip ships it alone.
- Older Editors still save: `schemas.validate` treats a document's `schemaVersion` as the current one when only the last number differs (every 0.N.x change to `shared/` is additive), so a cached tab or an un-updated PC is not locked out by a server update. A different 0.N or a major version, and every other schema error, is still refused with its paths.
- A new send replaces the old one (`services_jobs.replace_waiting`, called from `submit` after validation; `KERF_REPLACE_OLD_SENDS`, default on): the same pupil's earlier files that are `submitted` or `approved` are cancelled ("Replaced by a newer file (job-...)", event `replaced`), the new file takes a new ticket at the back, an activity hand-in that pointed at the old file follows the new one. `assigned`/`running` files, drafts and calibration marks are never touched, and a send that fails validation cancels nothing. The receipt lists `replaced`. The shared test settings turn it off (many tests put several files from one pupil in the queue); `TestANewSendReplacesTheOldOne` turns it on.
- Sign in with planner-004 (`sso.py`, design in `docs/AUTH-PLANNER-004.md`): `KERF_AUTH_MODE` = `planner` (default) | `both` | `pins` (tests/dev only), `KERF_SSO_ISSUER` (planner-004's origin, required unless `pins`), `KERF_SSO_AUDIENCE` (`kerf-sabre`), `KERF_SSO_JWKS_URL`, `KERF_SSO_CLIENT_EDITOR/ADMIN`. `security.current_principal` sends a bearer starting `eyJ` to `Verifier.principal`: RS256 only, header `typ: at+jwt`, `iss`/`aud`/`exp`/`nbf`/`sub` required, `client_id` must be ours, keys cached 5 min and refetched at most every 30 s on an unknown `kid` (stale keys keep working if DINO is down; no keys at all is 503 `sso_unavailable`). Roles: admin > teacher > technician > pupil, else 403; a JWT can never be station or platform. `sub` is the person's ID; no name or email is stored or logged. A DINO pupil is not auto-added to a class: a teacher adds their DINO ID as a pupil (the PIN is then unused). `GET /auth/config` tells the Editor how to sign in; `planner` mode answers `POST /auth/login` with 404 `sso_only`. Tests use a local key and a fake JWKS (`tests/test_sso.py`).
- **DINO is the only way in, and `technician` runs the stations** (shared 0.2.19, 0.2.20). `KERF_AUTH_MODE` defaults to `planner` (needs `KERF_SSO_ISSUER`; the server will not start without it). `security.lookup(..., people_tokens=False)` refuses any stored pupil/teacher/admin/technician token (401): only `station` (the Cutter) and `platform` tokens are stored tokens. `/auth/login` answers 404 `sso_only`; `POST /staff` and `kerf-admin create-token/import-pupils/reset-pin` and `POST /schools` with `adminId` are refused for people. `pins`/`both` exist for tests and local demos (`tests/conftest.py` sets `KERF_AUTH_MODE=pins`; `server/run-local.sh` and `start.py` do too). Role `technician` (from DINO `roles`, below teacher: admin > teacher > technician > pupil) is accepted wherever `require("station")` is (`security.require` adds it), may calibrate cameras and `skipQueue` (`Principal.can_override_queue`), and is refused everywhere that needs a teacher/admin. Tests: `tests/test_sso.py` (`TestOnlyDinoSignsPeopleIn`, `TestTechnician`).
- A technician may reject a queued (approved) file with a note (`POST /jobs/{id}/reject`, `require("teacher","technician")`; 409 for a file not yet approved); the stored reason is `Rejected at the laser: <note>` so the pupil can tell who stopped it. Picking a file ahead of the queue uses the existing `skipQueue` flag on frame/placement/assign (`Principal.can_override_queue`). `TestTechnicianPicksAndRejects` in `tests/test_sso.py`.
- **Display names** (shared 0.2.22; `models.Person`, `services_people.py`, `POST /auth/profile`): the Editor/Admin call it after a DINO sign-in; the server asks DINO's `/oauth/userinfo` with the caller's own bearer (`Verifier.userinfo_name`; tests replace `fetch_userinfo`), keeps only a cleaned `name` (no control characters, no `@`, 128 chars; never an email), and never logs it. Staff get `pupilName` on queue entries and job lists and `displayName` on class pupils and the progress grid, **only for their own school**; pupils never see anyone's name. `services_classes.remove_pupil` calls `people.forget`. `TestDisplayNames` in `tests/test_sso.py`.
